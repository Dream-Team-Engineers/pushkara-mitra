# Security policy

## Reporting a vulnerability

**Do not open a public issue.** Use [GitHub private vulnerability reporting](https://github.com/Dream-Team-Engineers/pushkara-mitra/security/advisories/new). Email contact: `SECURITY_EMAIL` is not set yet (OQ-005) and will be added here.

Please do not include real personal data or locations in your report.

## What to expect (targets, not guarantees)

| Step               | Target                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------- |
| Acknowledgement    | 2 working days                                                                         |
| Initial assessment | 7 days                                                                                 |
| Fix or mitigation  | By severity, see [vulnerability management](docs/security/vulnerability-management.md) |

## Regulatory reporting paths

If an incident may need reporting to CERT-In or under the DPDP Act, the incident commander (LEAD) starts the process in [incident-response](docs/security/incident-response.md) and [breach-response](docs/operations/breach-response.md). Counsel decides what is reported. Applicability and deadlines are unverified (OQ-007).

## Supported versions

| Version                                         | Supported |
| ----------------------------------------------- | --------- |
| `main` (pre-release, no production release yet) | Yes       |
