# Data model proposal (no migrations, no tables created)

Status: **PROPOSED — design only.** Prepared 2026-11-11 (IST). Companion to [ADR 0012](../decisions/0012-backend-architecture-and-d1.md). Nothing here creates a table, binding, migration or processing purpose. Every row's approval status is **NOT APPROVED** until the named gate in [BACKEND_FOUNDATION_DECISIONS](BACKEND_FOUNDATION_DECISIONS.md) is recorded. Personal-data tables stay blocked on residency (OQ-026), Time Travel handling (OQ-027), counsel (OQ-024) and the data fiduciary (OQ-023).

## Conventions (proposed)

- Primary keys: random opaque text ids (128-bit, base32), never sequential, never derived from a person.
- Times: UTC ISO-8601 text, set by the server. `STRICT` tables, `NOT NULL` by default, `CHECK` constraints for enums and lengths.
- Access: parameterised statements only, through one repository module; ownership resolved server-side from the session, never from a client-supplied id.
- Migrations: versioned, forward-only, expand-then-contract, applied by a reviewed workflow to one environment at a time; each environment has its own database. Local tests use synthetic rows only.
- Backup implication column assumes D1 Time Travel (7 days Free, 30 days Paid, always on, in-place restore; official docs retrieved 2026-11-11). A deleted row can return after a restore.
- Never in any table: coordinates, location history, card or payment-authentication data, OTPs, secrets, child records, missing-person records.

## Tables

Classification: **P** public, **I** internal, **S** staff personal data, **U** user personal data. Retention values are proposals for the retention decision (BF-08), not commitments.

## Not proposed

Live location (ADR 0004), missing-person reports and child or dependent records (ADR 0006; dedicated review), phone numbers or emails in our database (hold them in an identity provider if one is approved), advertising or profiling data, device fingerprints.

## Checks before any migration is written

1. The relevant BF decision is recorded with named reviewers and a repository revision.
2. Counsel has answered residency and retention for the tier (OQ-024, OQ-026, OQ-027).
3. A data-inventory row and notice exist for each personal field.
4. A test proves erasure, withdrawal, expiry and post-restore reconciliation using synthetic rows.
5. Separate databases exist per environment, created by an owner (not by this session).
