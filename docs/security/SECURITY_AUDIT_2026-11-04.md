## Why the code pause is not the complete H-01/H-02 fix

Removing the current automatic credential-bearing preview path prevents that path from running when the mitigation is merged. It cannot stop a malicious same-repo writer creating a new workflow that requests an any-branch environment, or rewriting unprotected main. Do not mark these High findings closed merely because the YAML mitigation or a checklist is merged.

Required closure evidence is verified external enforcement/credential isolation appropriate to the chosen plan and threat model, plus tests proving an unreviewed branch cannot access the credentials. Configured intent, a screenshot of secret names, agent review and green CI are not that evidence. Secrets should be rotated/revoked if actual exposure is found; this audit does not claim exposure or ask for blind rotation.

## Controls that remained intact

- Production callable workflow unconditionally fails without production environment/secrets/deployment commands; release has only pinned release-please. This is useful current defense, not externally enforced against unprotected-main writers.
- Manual preview bootstrap verifies main/current immutable SHA and actual independent final-head approval, with separate human account/namespace/single-writer preflight. GET-before-deploy is deliberately documented as non-atomic. These controls do not cure credential leakage in another workflow or unprotected main.
- No direct shell-expression injection found in examined PR text/title/dispatch handling: values are quoted environment variables and PR/SHA validation exists.
- Pinned third-party actions, scanner artifact checksums, least-privilege defaults and disabled persisted checkout credentials remain defense in depth.
- Current application is health/static scaffold; DO stub returns501 and uses no storage, migration has no personal-data tables, risky feature flags fail closed. No SQL injection, authenticated-resource authorization bypass or DOM-XSS path was established in current scaffold code. This is not a claim about features not yet built.

## Executed evidence and limitations

- Frozen install on the combined local preview/audit-helper mitigation snapshot; full `npm run check`: **95 tests in9 files**, lint/typecheck/format passed.
- Preview-pause guard verifies dispatch-only, no credential/environment/checkout/write path and visible failure; this is a narrow code regression check, not a substitute for external environment policy.
- Audit fixtures cover clean/moderate/high reports, network/tool exit, invalid/missing/inconsistent evidence and the old catch-all false success. Actual informational audit completed with27 moderate entries,0 high/critical.
- `npm audit --omit=dev --audit-level=high`: zero vulnerabilities. Full audit:27 moderate entries, no high/critical.
- Explicit-path actionlint passed; offline zizmor reported no findings with one existing suppression. Automated lint alone did not establish the credential trust boundary.
- Gitleaks scanned43 main-history commits with redaction and found no leaks in that scan. No credential stores or secret values were inspected; binaries/cloud logs are not comprehensively covered by this result.
- Independent runtime-fix evidence:80 real local HTTP cases over four configurations, no remote deployment. Separate original-shell prototype is not shipped main; its upgrade/offline-readiness correctness issue was caught during review and was corrected locally before review submission.
- Local Semgrep/CodeQL, independent penetration testing, cloud token privilege review, live environment abuse tests and full product security/UAT were not performed. Existing CI SAST results and local static/manual audit are distinct evidence.
